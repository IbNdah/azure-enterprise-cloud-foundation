# 1. Executive Summary

As part of the **OneCloud 2030** transformation program, Mandara Global provides a centralized set of platform services shared across all Azure Landing Zones.

This reference architecture defines the common platform capabilities that support governance, identity, networking, security, monitoring, and operational management.

By centralizing these services, the platform ensures consistency, scalability, and operational efficiency across the enterprise.

---

# 2. Purpose

The purpose of this reference architecture is to define the shared services that every Landing Zone consumes.

The architecture enables:

- Standardized platform capabilities
- Centralized governance
- Reusable enterprise services
- Consistent operational model
- Simplified workload onboarding

---

# 3. Scope

This architecture applies to:

- Identity Services
- Networking Services
- Security Services
- Monitoring Services
- Governance Services
- Platform Management Services

---

# 4. Architecture Overview

Platform capabilities are centrally managed by the Cloud Platform Team and consumed by business workloads deployed into Landing Zones.

Application teams focus on delivering business solutions while relying on standardized enterprise services.

# 6. Core Platform Services

| Service Domain | Core Services |
|----------------|---------------|
| Identity | Microsoft Entra ID, RBAC, Managed Identities |
| Connectivity | Hub Network, Firewall, Private DNS, VPN, ExpressRoute |
| Governance | Management Groups, Azure Policy, Naming & Tagging |
| Security | Defender for Cloud, Key Vault, Private Link |
| Operations | Azure Monitor, Log Analytics, Managed Grafana |

---

# 7. Design Principles

The platform services architecture follows the enterprise principles defined in ARC-001.

Key principles include:

- Shared Services First
- Platform over Projects
- Security by Design
- Infrastructure as Code
- Standardization over Customization
- Observability by Default
