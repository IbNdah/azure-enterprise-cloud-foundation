# SEC-004 — Security Exceptions

## Purpose
Security exceptions document cases where a defined security control cannot be applied as designed.

## Requirements
Every exception must contain:
- **Scope:** affected resource, subscription, or workload.
- **Control:** security requirement being waived.
- **Justification:** technical/business reason.
- **Risk:** identified security impact.
- **Compensating control:** alternative protection where applicable.
- **Owner:** accountable person/team.
- **Expiry / Review date:** exception must be time-bound.

## Principles
- Exceptions are **not** a replacement for security controls.
- Exceptions must be narrow and explicitly approved.
- Permanent exceptions should be avoided.
- Expired exceptions must be reviewed and either renewed or removed.

## Current Status
